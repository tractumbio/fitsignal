# GCP Schema for FitSignal

This document defines a recommended schema for storing resume analysis data on Google Cloud. It is based on the current FitSignal design and backend AI response schema.

## BigQuery Schema

Recommended dataset: `fitsignal`
Recommended table: `resume_scores`

```sql
CREATE TABLE `fitsignal.resume_scores` (
  resume_id STRING NOT NULL,
  created_at TIMESTAMP NOT NULL,
  source_file_name STRING,
  target_role STRING,
  resume_text STRING,
  candidate_name STRING,
  status STRING,

  overall INT64,
  likelihood INT64,
  verdict STRING,
  verdict_note STRING,
  recommendation STRING,
  recommendation_note STRING,

  dims ARRAY<STRUCT<
    name STRING,
    score INT64,
    note STRING
  >>,

  criteria ARRAY<STRUCT<
    label STRING,
    ok BOOL
  >>,

  strengths ARRAY<STRING>,
  flags ARRAY<STRING>,
  recs ARRAY<STRING>,

  raw_response JSON,
  updated_at TIMESTAMP,
  notes STRING
);
```

### Notes
- `resume_id` can be generated by the backend as a UUID.
- `created_at` is the ingestion timestamp when analysis was requested.
- `raw_response` stores the full AI response object for auditing and debugging.
- `status` can be one of `PENDING`, `COMPLETED`, `FAILED`.
- `target_role` captures the role selected by the recruiter.

## Optional Cloud Storage Layout

If you also want to store raw resume uploads or generated PDF reports, use a bucket layout like:

- `gs://fitsignal-uploads/resumes/{resume_id}.txt`
- `gs://fitsignal-uploads/reports/{resume_id}.pdf`

## Recommended GCP Services

- Cloud Run for backend service (`deploy/server.js`)
- BigQuery for scored results and analytics
- Cloud Storage for raw resume files and export artifacts
- Secret Manager for `ANTHROPIC_API_KEY`

## Suggested Usage

1. Save uploaded resume text and metadata to BigQuery.
2. Send `resume_text` to the AI scoring backend.
3. Store parsed result fields back into `fitsignal.resume_scores`.
4. Use BigQuery views or dashboards to analyze common strengths, flags, and recommendation distribution.
